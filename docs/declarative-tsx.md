
# Декларативный TSX

Декларативный TSX представляет собой подмножество TypeScript с раширением JSX, ограниченное использованием строго определённого множества синтаксических конструкций и дополнительных правил, использующих информацию о типах. Модули на декларативном TSX обрабатываются специальным компилятором, наделяющим код семантикой инкрементальных вычислений.

## Назначение декларативного TSX

Смысл декларативного TSX - ограничить язык TypeScript таким образом, чтобы:

1. Типизация была строгой, чтобы выведенным типам можно было доверять
2. Гарантировать определённые инварианты, на которые полагается компилятор при преобразованиях кода.
3. Убрать лишний синтаксис, чтобы не усложнять реализацию компилятора и сделать язык более узкоспецифичным (DSL) для описания логики UI

## Использование декларативного TSX

Так как декларативный TSX является подмножеством TSX, typechecker и TypeScript language server воспринимают его без дополнительных настроек. Не требуется ставить никаких дополнительных расширений для VS Code, но компилятор может сообщать свои синтаксические и семантические ошибки в добавление к ошибкам TypeScript.

Модули на декларативном TSX располагаются в проекте наряду с обычными TypeScript-модулями.

## Ограничения декларативного TSX, применяемые к TypeScript

Ограничения применяются для файлов с расширениями `.decl.ts` и `.decl.tsx`. Далее приводится неформальное описание ограничений, понятное для разработчиков, знакомых с TypeScript.

- Только ESM (ECMAScript modules), никаких `require` и `module.exports`
- Запрет ключевых слов:
  - Заведомо не рекомендуемые к использованию конструкции:
    - `var` - использовать только `let` и `const` для объявления переменных и констант.
    - `delete` - чтобы запретить изменять структуру уже созданных объектов. Тем более, TypeScript плохо учитывает результат применения `delete`.
    - `namespace` - специфичная для TypeScript конструкция, не рекомендуется больше использовать даже по документации самого TypeScript.
    - `enum` - запрещается как специфичная для TypeScript конструкция, приводящая к emit дополнительного кода. TypeScript должен использоваться как typechecker и преобразовываться в JavaScript простым стиранием типов.
    - `function` - использовать только стрелочные функции.
    - `for`-`in` - циклы. Разрешить только `for`-`of`
  - связанные с объектно-ориентированным программированием:
    - `class` - обходимся без классов, только примитивные типы, plain объекты, массивы, стрелочные функции и некоторые встроенные типы данных (например, Date).
    - `this` - не нужен, так как нет классов и стрелочные функции не имеют своего `this`.
    - `new` - не нужен, так как все объекты создаются объектными выражениями, а если объект создаётся только через `new`, то вынести создание в специальную утилитную функцию.
    - `instanceof` - скорее всего не нужен, так как по концепции мы отходим отойти от представлений о прототипах в языке, но может понадобится при работе с Web API, тогда просто вынести проверку в утилитную функцию-typeguard.
    - `get`, `set` - запрещено делать свойства с нестандартными методами доступа, чтобы не имитировать настоящие свойства. В должно быть явно обозначено, где настоящий доступ к хранимым данным, а где могут произойти дополнительные вычисления.
    - `interface` - использовать объектные типы, объявленные через `type`. Нам не нужен declaration merge.
  - связанные с императивным программированием:
    - `while` - использовать вместо циклов рекурсию или проход по массивам с помощью методов массива или `for`-`of`
    - `do` - циклы с постусловием тоже запрещены
    - `for( ; ; )` - циклы со счётчиком
  - связанные с исключениями:
    - `throw` - не выбрасывать исключения в декларативном языке
    - `try`-`catch`-`finally` - не перехватывать исключения. Работа с исключениями должна оставаться вне языка. Строгая типизация позволяет явно описать ожидаемые ошибочные ситуации.
- Запрет небезопасных операторов:
  - операторы нестрогого сравнения `==` и `!=` - использовать для сравнения только `===` и `!==`. Не полагаться на неявные приведения типов.
  - spread-оператор для объектов - может привести к ошибкам типизации. Можно разрешить использование только в начале объектного выражения и только один раз. Таким образом, не допускаем бесконтрольно мержить объекты, разрешаем только клонировать с заменой некоторых свойств.
- Запрет синтаксиса, связанного с динамической природой объектов:
  - использование  оператора `[]` для обращения к свойствам объектов. Объекты должны быть с чётко обозначенной структурой, и вычислимые имена свойств - признак нежелательного стиля программирования с динамической природой объектов.
  - индексная сигнатура в типах объектов. Объекты должны иметь строго описанную структуру. Если нужно неопределённое множество свойств, то стоит воспользоваться Map вместо объектов.
  - сигнатура вызова объекта как функции в типах объектов. Функция должна оставаться функцией и иметь тип стрелочной функции, никакие другие свойства функционального объекта использоваться не должны. Вызов функции как конструктора тоже запрещён.
- Запрет синтаксиса ООП:
  - методы в объектах - использовать свойства со значениями стрелочных функций
  - методы в типах объектов - не рекомендуются самим TypeScript из-за бивариантности
  - операции с прототипами - предполагается, что никакого наследования нет, все объекты наследуются только от Object либо не имеют прототипа вовсе. Некоторые встроенные типы данных, например, массивы, функции, Date, Set, Map и т.д., являются исключениями, но они и не используются как обычные объекты. Вместо наследования и классов лучше применять Date Oriented Design и работать с объектами как с данными с помощью отдельных функций.
- Запрет небезопасной типизации:
  - `any` - запрещён в любом виде, как явно, так и неявно
  - `as` - запрещено небезопасное приведение типа к подтипу, разрешено только приведение к надтипу
  - приведение объектных типов с `readonly`-свойствами к объектным типам с теми же свойствами без `readonly`
  - приведение объектных типов с опциональными свойствами к объектным типам без этих же опциональных свойств
  - приведение функциональных типов с опциональными параметрами к функциональным типам без этих опциональных параметров
  - изменяемые свойства со значениями функциональных типов
  - `let`-переменные со значениями функциональных типов
  - union-типы функциональных типов с объектными типами и массивами.

Так как инкрементально исполняемый код должен работать в двух раздельных фазах, требуется явно разделять, где какая фаза может выполняться. Будет существовать особая функция-маркер 'action' типа `(callback: () => void) => void`, которую можно вызывать только с аргументом стрелочной функции в виде `action(() => { /*код*/ })`, где код внутри подчиняется особым правилам. Вне кода, обёрнутого в action, запрещены все операторы присваивания и мутирующие операции массивов, разрешено использование идентификаторов и типов, импортированных только из других модулей декларативного TSX или пакета 'rwrtw' или некоторых встроенных в стандартную библиотеку TypeScript. Внутри кода action разрешены присваивания и мутирующие операции массивов.
