# RWRTW

RWRTW - это Web UI-фреймворк с "fine-grained" реактивностью, основанной на сигналах, декларативным синтаксисом, основанном на JSX, и оптимизирующим компилятором.

## Овервью

RWRTW - это реализация паттерна MVVM с автоматической синхронизацией модели, промежуточных данных и представления

RWRTW состоит из следующих слоёв, каждый их которых может использоваться непосредственно самостоятельно:

- **Core** - набор библиотек на TypeScript:
  - реализация слоя абстракции манипуляций с DOM
  - реализация сигнальной реактивности
  - простой DSL из типизированных функций, чтобы связывать всё вместе
- **Runtime TSX** - реализация JSX-runtime, использующая примитивы из Core
- **Template TSX** - трансформер JSX на этапе сборки, превращающий фрагменты JSX в оптимизированные шаблоны
- **Declarative TSX** - компилятор декларативного кода на TypeScript, реализация компилируемой реактивности

## Принципы разработки и ограничения

- Отсутствие сторонних зависимостей, только vanilla JS и API браузера
- Прозрачная логика работы для разработчиков, знакомых с HTML, CSS, DOM API, event handling, WebComponents и т.д.
- Отсутствие лишних слоёв абстракции, реализация настолько близко к DOM API, насколько возможно
- Минимальный размер бандла не менее важен, чем скорость работы
- Использование возможностей современного JavaScript и нативных возможностей браузера, не учитываем устаревшие подходы
- В приоритете Developer Experience
- Активное использование TypeScript, пользователи фреймворка тоже должны использовать TypeScript
- Весь код должен быть максимально строго типизирован, запрещены any и небезопасные приведения типов
- Код, дружественный для минификации:
  - Не использовать строковые литералы как ключи объектов
  - Не анализировать сигнатуры функций в runtime
- Код, дружественный для tree-shaking:
  - Разделение на модули
  - Использовать статически разрешаемые экспорты
  - Не использовать лишний динамический полиморфизм или косвенные вызовы функций, если это можно сделать статически
  - Не запутывать связи модулей, минимизация импортов, отсутствие циклических зависимостей
- Минимизация использования памяти, не создавать промежуточные объекты, массивы и замыкания без необходимости
- Запрещены операции с прототипами и monkey patching
- Запрещено создание новых свойств на DOM-узлах и других встроенных типов объектов
- Запрещено использование опасного "innerHtml" и других подобных манипуляций
- Не создавать скрытые DOM-узлы для служебных целей, такие как узлы с "display: none", пустые текстовые узлы, узлы комментариев
- Не заниматься метапрограммированием со свойствами объектов и параметрами функций:
  - Не предполагать никакие соглашения об именовании, которые подразумевают парсинг имён
  - Не использовать вычислимые имена свойств
  - Не использовать dependency injection, ограничиться статическим связыванием модулей
  - Не использовать декораторы, JavaScript Proxy, нетривиальные дескрипторы свойств
- Не создавать специальных языков в строковых литералах:
  - Не создавать никаких соглашений о содержимом строковых литералов
  - Не парсить строки по соглашениям, не анализировать их содержимое посимвольно


## Road map

- v0.0.x:
  - **Понимание основных идей, концепций**: компонентная модель, цикл обновления,необходимые утилитные функции
  - **Понимание идей реализации основных сложных частей**: жизненный цикл состояния, операции с DOM, DSL шаблонов, реактивность, условный рендеринг и динамические списки
  - **Понимание структуры модулей проекта** и зависимостей между ними
  - **Черновая версия публичных API** всех модулей
  - **Тесты для публичного API** всех модулей
  - **Настройка зависимостей для разработки и публикации**
  - **Черновик компилятора декларативного TSX**
- v0.1.x:
  - **Финальная версия публичного API**, в том числе декларативного TSX
  - **Тесты на все документированные случаи использования публичного API** для проверки обратной совместимости будущих версий
  - **Документация на публичное API**, описание концепций, инструкции по быстрому старту, небольшой туториал
  - **Плагины для бандлеров**, например, Vite, RsPack
  - **Примеры проектов**: с компонентами с состоянием, без состояния, обработка событий, привязка данных, интерактивные формы с валидацией, CRUD
- v0.2.x:
  - **Режим разработки**, при котором выполняется больше проверок в runtime и подключение dev tools
  - **Обработка ошибок**, отделение ошибок при разработке от ожидаемых ошибок в продовой сборке
  - **Асинхронная логика**, включая примеры с таймерами и запросами на сервер
  - **Context API**
  - **Реализация идей по оптимизации**: компиляция шаблонов JSX, сигналы с фиксированным списком зависимостей, избегание лишних computed-узлов
  - **Простые бенчмарки**, иллюстрирующие работу оптимизаций
  - **Интеграции** с другими state managers и библиотеками стилей
  - **Поддержка Web Components**: как минимум, Custom Elements и Shadow DOM, реактивность атрибутов
  - **History API** и простейший Router
  - **Простейший UI kit** без дизайн-системы
- ...
